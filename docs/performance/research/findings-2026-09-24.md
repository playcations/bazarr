## 2. FR2 (shared provider discovery) — verified
- Confirmed: `generate_subtitles` loops per requirement (download.py:69) and calls `download_best_subtitles(languages={language})` with a single-element set (:90); the wrapper runs a full `pool.list_subtitles` each time (core_persistent.py:73-74). Duplication comes entirely from this split (commit 2e2626ce split them for cutoff).
- **Benefit is broader than spec says**: plain multi-language profiles (`{fr, en}`) also double their searches, not only HI/forced variants. ~2–3× fewer listing requests for items with multiple missing requirements; zero for single-requirement items and upgrades.
- Spec corrections:
  - No forced-provider pool config to race — `_set_forced_providers` is a no-op (utils.py:99-104).
  - **Missing hazards**: pool selection filters by basename only (core.py:562) → forced candidates would leak across requirements in a union pool; `compute_score` mutates `s.matches` in place (score.py:122-154) → HI match leakage and hash-truncation causing false rejections on a second pass; `content/score/use_original_format` set on candidate objects → a saved subtitle can be re-selected; addic7ed/embedded return HI rows under union listing; gestdown dedupe by `s.id` collapses language copies; union listing costs per-language providers (gestdown) calls that today are skipped when cutoff hits early.
  - Existing bug: `hi_mode` lookup matches profile items on language+forced only (download.py:80-86).
  - Manual search already does list-once + local filter (manual.py:71-124) — reuse that pattern.
- No tests cover `generate_subtitles`, selection, or cutoff recheck today.
- Design: `list_candidates()` + `select_best(..., exclude_ids)` in core_persistent.py (forced-exact filter, per-requirement shallow copy with own `matches`), keep legacy `download_best_subtitles`; `generate_subtitles` lists once, keeps per-requirement cutoff-recheck/yield loop; legacy fallback on listing error; deterministic requirement order.

## 3. FR1 (pack reuse) — verified
- SubDL rarely downloads archives: `unpack=1` default with per-file URLs (subdl.py:381, 551-585); its season fallback search already returns other episodes' members + URLs → fan-out needs no archive.
- SubSource already caches archives 15 min + queries 1 h (subsource.py:35, 247, 635-650).
- SuperSubtitles marks every subtitle `is_pack=True` (supersubtitles.py:81).
- Shared `get_subtitle_from_archive`/`_get_matching_sub` ignore season and return one member's content (providers/utils.py:46-139); only the mixin (mixins.py:104-111) is season-aware. Need new `enumerate_archive_members()`.
- Pack providers inject a synthetic `episode` match (subsource.py:97-99, assrt.py:177-179, legendasdivx.py:117-120) → per-member rescoring mandatory.
- Blacklist is global per (provider, id) (pool.py:22) → pack-wide ids blacklist every episode.
- Spec missed Assrt, Subx, Subf2m, Subclub as pack providers.
- Mainstream providers (OpenSubtitles.com, Addic7ed, Gestdown, Embedded) have no pack support. Value is concentrated in SubDL/SubSource/regional providers (anime, Arabic/Persian, HU, SR/HR, TR, PT, ZH).
- Design: Phase A — bounded in-memory run cache keyed by provider+pack id for archive providers + `enumerate_archive_members()` (no behavior change). Phase B — SubDL-only cross-episode fan-out via a `save_external_candidate(episode_id, subtitle)` helper reusing scoring/save/process/history with fresh eligibility checks (monitoring, exclusions, profile, missing, cutoff), no adaptive stamping from fan-out. Phase C — more adapters / scheduler integration.

## 4. FR3 (parallel scheduler) — verified
- Confirmed: wanted loops serial (series.py:148-162, movies.py:135-147), `break` the whole job when all providers throttled; `concurrent_jobs` (default 4) runs whole jobs in threads (jobs_queue.py:519-552, small overshoot race).
- "Search Enabled Providers Simultaneously" = `general.multithreading` → `SZAsyncProviderPool`, new ThreadPoolExecutor per list call, one worker per provider (core.py:733-762); downloads serial. Already ~4×N provider threads possible.
- **Spec wrong**: RateLimiting mixin is dead code since 7343b1d15; `DomainThrottler` has no reservation, wall-clock time, domain-only keys, no Retry-After parsing. `RetryingSession` retries are invisible to any limiter.
- Throttle state: module dict `tp`, no lock, written with `str()` non-atomically and read back with **`eval()`** (get_providers.py:561-577); `throttled_count` unlocked with `time.sleep(5)` in provider thread.
- `_pools` unlocked; `SZProviderPool.update` mutates in place; lazy provider init unlocked; `_check_lifetime` can terminate providers under another job. **Cross-thread provider sharing already happens today** via `concurrent_jobs` (existing hazard).
- DB: NullPool + AUTOCOMMIT + WAL + busy_timeout 60s (database.py:78-99). Spec 7.1.5 confirmed: `process_subtitle` runs sync (inline), post-processing, Sonarr/Radarr notify, events, Plex/Jellyfin, webhook before the Wanted caller writes index/history.
- **Existing bug (not in spec)**: multi-language failed-attempt stamping rebuilds from the original `failedAttempts` each loop pass → only the last language's stamp survives (series.py:69-71, movies.py:67-69). Also `providers_list` snapshotted pre-search so providers that fail mid-search count as "no match"; delay setting parsed as `[:1]`.
- Whisper fallback fires when no subtitle downloaded across the pool's candidates (core.py:645-657) → spec risk 7.1.6 is real under per-provider dispatch.
- No per-media locks anywhere.
- **Assessment**: spec (leases, generations, state machine, journaled ack'd writer, multi-scope rate governance) is disproportionate for upstream; first-acceptable-provider changes result selection (today best score across all providers wins) — make opt-in or drop.
- Minimal viable FR3: `wanted_parallel_items` setting (default 1 = current behavior), ThreadPoolExecutor over item IDs, process-wide per-provider BoundedSemaphore around `list_subtitles_provider`/`download_subtitle`, per-media lock registry shared by wanted/mass-download/manual/webhook save paths, semaphore on ffsubsync, Retry-After-aware `provider_throttle` (opt-in per provider), keep best-score selection. Later: per-requirement(+provider) attempt table borrowing #3397's design; post-commit side effects only if needed.

## Dead end: storing Sonarr's series TMDB id (2026-09-26)
`feature/sonarr-series-tmdb-id` stored Sonarr v4's `tmdbId` in a new `table_shows.tmdbId` column (with a migration)
so TMDB lookups could skip `/find`. Checked on the live library: TMDB `/find` by TVDB id returned exactly Sonarr's
TMDB id for all 269 shows that have one, and `/find` results are already cached per show. The only gain was one
cached request per show against a schema change, so the branch was dropped and removed from the NAS database.
